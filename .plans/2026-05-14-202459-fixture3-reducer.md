# fixture3 Reducer Plan

## Goal

Add `fixture3 reduce` as a deterministic reducer for oversized copied-project fixtures.

The reducer shrinks fixture content while preserving a suite-owned behavior contract. It produces machine-readable proof metadata that shows every reducer pass, every accepted removal, and every rejected removal.

The guarantee is:

- No built-in reducer pass found removable content while preserving the configured contract.

The guarantee is not:

- global mathematical minimality
- minimality across alternate fixture designs
- semantic equivalence outside the configured contract

## Final Decisions

- `reduce` mutates the fixture in place by default.
- `--dry-run` runs the same reducer against backups and restores all accepted edits before exit.
- `--dry-run` prints the proof report to stdout and does not write the proof file.
- Normal mode writes proof metadata to `reduce.proof`.
- `reduce.proof` lives inside the fixture root by default as `.fixture3-reduce.json`.
- `reduce` accepts exactly one `--suite`.
- `reduce` does not accept `--all`, `--tag`, or `--feature`.
- `reduce` does not accept `--pass`.
- `reduce` exits `0` after a completed reduction with a passing final contract.
- `reduce` exits `2` for setup errors, generated-directory violations, baseline contract failure, oracle command failure, or final contract failure.
- `reduce` does not use exit code `1`.
- `walkdir` is the filetree traversal dependency.
- `ignore` is not used for the reducer.
- Guardrail3 `g3-workspace-crawl` is not used for the reducer.
- `toml_edit` is the TOML reducer dependency.
- `treereduce` and `tree-sitter-rust` are the Rust source reducer dependencies.
- `treereduce` runs with one job in the first implementation.
- Symlinks under `reduce.root` are rejected.
- Generated folders are rejected, not reduced.
- Source reduction is controlled by explicit manifest globs.
- Reducer pass order is fixed in code.
- Contract matching uses JSON row matching for stdout and text exclusion for stderr.
- Substring matching is not used for stdout contract requirements.
- The verifier fixture lives under `examples/fake-project/reducer-project`.

## Problem

Copied-project fixtures become too large because they preserve unrelated project content.

The reducer removes:

- unrelated files
- unused Cargo dependencies
- unused TOML keys
- unused Rust source items
- empty directories left after accepted removals

The reducer rejects:

- generated directories
- symlinks
- unsupported file types during reducer-owned copy operations
- suites without a reducer contract

## Command Surface

Supported commands:

```bash
fixture3 reduce --suite <suite>
fixture3 reduce --suite <suite> --dry-run
fixture3 reduce --suite <suite> --json
```

Rejected command shapes:

```bash
fixture3 reduce --all
fixture3 reduce --tag <tag>
fixture3 reduce --feature <feature>
fixture3 reduce --suite <suite> --pass filetree
fixture3 reduce --suite <suite> --proof <path>
fixture3 reduce --suite <suite> --write
```

Reason:

- mutation across several suites is not part of the first reducer contract
- individual pass execution exposes implementation details and creates partial states
- proof path belongs in the manifest
- normal mode already writes

## Manifest Shape

Each reducible suite contains a `reduce` block.

```yaml
suites:
  copied-rust-project:
    fixtures:
      - "examples/fake-project/reducer-project/input.json"
    command:
      argv:
        - "bash"
        - "examples/fake-project/scripts/replay-reducer-project.sh"
        - "{fixtures}"
      ok_exit_codes:
        - 0
    output:
      format: "json"
    storage:
      approved_dir: "examples/fake-project/behavior/approved/reducer-project"
      received_dir: ".fixture3/reducer-project"
      diff_dir: ".fixture3/reducer-project"
    reduce:
      root: "examples/fake-project/reducer-project/project"
      proof: "examples/fake-project/reducer-project/project/.fixture3-reduce.json"
      protected:
        - "Cargo.lock"
      generated_dirs:
        - "target"
        - ".git"
        - ".cargo-target"
        - "node_modules"
        - "dist"
        - ".fixture3"
        - ".goldencheck"
      source:
        rust:
          include:
            - "src/**/*.rs"
          exclude:
            - "src/generated/**/*.rs"
      contract:
        exit_code: 0
        stdout:
          format: "json"
          require_rows:
            - rule: "workspace_root"
              severity: "error"
          forbid_rows:
            - rule: "unexpected_generated_state"
        stderr:
          forbid_text:
            - "panicked at"
```

Manifest rules:

- `reduce.root` is required.
- `reduce.proof` is required.
- `reduce.contract` is required.
- `reduce.source.rust.include` is required.
- `reduce.generated_dirs` uses the default list shown above when absent.
- `reduce.protected` uses an empty list when absent.
- All reducer paths are relative to the manifest directory.
- `reduce.proof` must be under `reduce.root`.
- `reduce.root` must not be the repository root.

## Contract Semantics

The oracle runs the suite command and evaluates the reducer contract.

Exit-code contract:

- actual command exit code must equal `reduce.contract.exit_code`

Stdout contract:

- stdout must parse as JSON
- `stdout.require_rows` contains partial JSON objects
- each required row must match at least one object anywhere in the stdout JSON tree
- a row matches when every field in the required row exists with the same JSON value
- `stdout.forbid_rows` contains partial JSON objects
- forbidden rows must match zero objects in the stdout JSON tree

Stderr contract:

- each `stderr.forbid_text` string must be absent from stderr

Unsupported contract forms:

- stdout substring requirements
- JSONPath expressions
- count ranges
- regex matching

Reason:

- partial JSON row matching is enough for fixture behavior rows
- JSONPath adds dependency and selector semantics before the first reducer needs them
- stdout substring matching is too weak for a reducer oracle

## Execution Flow

`fixture3 reduce --suite copied-rust-project` runs this sequence:

1. Load manifest.
2. Resolve exactly one suite.
3. Convert `suite.reduce` into reducer config.
4. Reject missing reducer config with exit `2`.
5. Reject `reduce.root` outside the repository with exit `2`.
6. Reject `reduce.root` equal to the repository root with exit `2`.
7. Run baseline oracle.
8. Reject baseline contract failure with exit `2`.
9. Compute `baseline_hash`.
10. Run `generated-dirs` pass.
11. Run `filetree` pass.
12. Run `toml` pass.
13. Run `treereduce-rust` pass.
14. Remove empty directories.
15. Run final oracle.
16. Reject final contract failure with exit `2`.
17. Compute `final_hash`.
18. Write proof file in normal mode.
19. Print proof JSON in `--json` mode.
20. Print short text summary in normal text mode.

Pass order:

```text
generated-dirs -> filetree -> toml -> treereduce-rust -> empty-dirs
```

## Mutation Model

Normal mode:

- candidate edits are applied to the real fixture root
- every candidate starts with a backup
- accepted edits keep the modified fixture
- rejected edits restore from backup
- final proof is written to `reduce.proof`

Dry-run mode:

- candidate edits are applied to the real fixture root
- every accepted edit is recorded
- every accepted edit is restored before exit
- rejected edits restore immediately
- proof JSON is printed to stdout
- proof file is not written
- final filesystem state equals the state before the command started

Crash recovery:

- backups are stored under `.fixture3/reduce-backups/<suite>/<run-id>`
- backups are deleted after successful normal-mode completion
- dry-run deletes backups after successful restoration
- startup detects existing backup directories and exits `2` with the backup path
- no automatic recovery runs in the first implementation

## Filetree Pass

Traversal:

- use `walkdir`
- follow symlinks: false
- include hidden files
- include gitignored files
- sort candidates lexicographically by repository-relative path
- include regular files only
- reject symlinks
- reject special files

Candidate rules:

- skip paths in `reduce.protected`
- skip `reduce.proof`
- skip suite storage paths
- skip `.fixture3/reduce-backups`
- skip directories listed in `reduce.generated_dirs` after the generated-dir pass has checked them

Algorithm:

1. Build sorted regular-file candidate list under `reduce.root`.
2. Move candidate file to backup.
3. Run oracle.
4. Keep deletion when oracle passes.
5. Restore file when oracle fails.
6. Repeat until one complete pass removes zero files.
7. Remove empty directories under `reduce.root`.
8. Record tried, removed, and kept paths.

## Generated Directory Pass

Generated directories are rejected before any reducer mutates content.

Default generated directory names:

- `target`
- `.git`
- `.cargo-target`
- `node_modules`
- `dist`
- `.fixture3`
- `.goldencheck`

Algorithm:

1. Walk `reduce.root` with `walkdir`.
2. Collect directories whose final path component is in `reduce.generated_dirs`.
3. Exit `2` when the collection is non-empty.
4. Record checked directory names in proof when the collection is empty.

This pass does not delete generated directories.

## TOML Pass

Files:

- every `Cargo.toml` under `reduce.root`
- every `*.toml` under `reduce.root` not listed in `reduce.protected`

Dependency:

- `toml_edit`

Candidate types:

- remove one `[dependencies]` entry
- remove one `[dev-dependencies]` entry
- remove one `[build-dependencies]` entry
- remove one `[features]` entry
- remove one `[workspace.dependencies]` entry
- remove one `[workspace.members]` value
- remove one package metadata key under `[package.metadata]`

Algorithm:

1. Parse TOML with `toml_edit`.
2. Generate candidates in the order listed above.
3. Write one candidate edit.
4. Run oracle.
5. Keep edit when oracle passes.
6. Restore file when oracle fails.
7. Repeat until one complete pass removes zero TOML candidates.
8. Record tried, removed, and kept TOML paths.

Invalid TOML after an edit is a reducer bug and exits `2`.

## Rust Source Pass

Files:

- Rust files matched by `reduce.source.rust.include`
- protected paths are excluded
- paths matched by `reduce.source.rust.exclude` are excluded

Dependencies:

- `treereduce`
- `tree-sitter-rust`

Runtime settings:

- `jobs = 1`
- `min_reduction = 2`
- `passes = 2`
- `delete_non_optional = false`
- replacements: `type_identifier -> ()`

Algorithm:

1. Build sorted Rust file list from include and exclude globs.
2. Parse the current file with `tree-sitter-rust`.
3. Skip files with parse errors and record them as skipped.
4. Run `treereduce` with a fixture3 `Check` adapter.
5. For every candidate source from `treereduce`, write the candidate to the real file path.
6. Run oracle.
7. Return interesting when oracle passes.
8. Restore previous source when oracle fails.
9. Keep the final reduced source when `treereduce` finishes and final oracle passes.
10. Restore original source and exit `2` when final oracle fails.
11. Record tried, changed, unchanged, and skipped files.

No external `treereduce-rust` binary is called.

## Symlink Policy

Symlinks under `reduce.root` are rejected with exit `2`.

Reason:

- symlinked real packages hide fixture dependencies
- reducer proof needs physical content
- the first implementation uses concrete copied or stubbed content only

## Tree Hashing

The reducer computes a stable hash for `reduce.root`.

Algorithm:

1. Walk with `walkdir`.
2. Reject symlinks and special files.
3. Sort regular files by relative path.
4. Hash each relative path as UTF-8 bytes.
5. Hash a zero byte separator.
6. Hash file bytes.
7. Hash another zero byte separator.
8. Return `sha256:<hex>`.

Use the existing `sha2` dependency.
