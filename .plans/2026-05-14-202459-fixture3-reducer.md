# fixture3 Reducer Preliminary Plan

## Goal

Add a `fixture3 minimize` command that reduces oversized copied-project fixtures while preserving an explicit behavior contract.

The command must make this guarantee:

- No configured reducer pass found removable fixture content while preserving the configured contract.

The command must not claim:

- The fixture is globally minimal.
- The fixture is minimal across every possible alternate fixture design.
- The reduced project is semantically equivalent outside the configured contract.

## Problem

Some fixtures are copied from real projects and then modified. That makes them too large:

- unrelated files stay in the fixture
- generated folders can be accidentally committed
- real packages can stay when a stub would be enough
- source files can contain unrelated functions, modules, and branches
- future agents cannot tell whether remaining content is intentional

The reducer should turn fixture minimization into a mechanical process with proof metadata.

## User-Facing Command

Initial command:

```bash
fixture3 minimize --suite <suite>
```

Useful options:

```bash
fixture3 minimize --suite <suite> --dry-run
fixture3 minimize --suite <suite> --pass filetree
fixture3 minimize --suite <suite> --pass toml
fixture3 minimize --suite <suite> --pass treereduce-rust
fixture3 minimize --suite <suite> --json
fixture3 minimize --suite <suite> --proof <path>
```

Selector policy:

- V1 accepts exactly one `--suite`.
- Do not support `--all`, `--tag`, or `--feature` for mutation in V1.
- Reduction mutates fixture files, so broad selectors need a stronger safety model.

## Manifest Shape

Add an optional `reduce` block under each suite:

```yaml
suites:
  copied-rust-project:
    fixtures:
      - "behavior/fixtures/copied-rust-project/*"
    command:
      argv:
        - "bash"
        - "scripts/replay-copied-rust-project.sh"
        - "{fixtures}"
      ok_exit_codes:
        - 0
    output:
      format: "json"
    storage:
      approved_dir: "behavior/approved/copied-rust-project"
      received_dir: ".fixture3/copied-rust-project"
      diff_dir: ".fixture3/copied-rust-project"
    reduce:
      root: "behavior/fixtures/copied-rust-project/project"
      proof: "behavior/fixtures/copied-rust-project/.fixture3-reduce.json"
      protected:
        - "Cargo.lock"
        - "fixture3.yaml"
      generated_dirs:
        - "target"
        - ".git"
        - ".cargo-target"
        - "node_modules"
        - "dist"
        - ".fixture3"
        - ".goldencheck"
      contract:
        exit_code: 0
        require:
          - '"rule": "workspace_root"'
          - '"severity": "error"'
        forbid:
          - "panicked at"
      passes:
        - generated-dirs
        - filetree
        - toml
        - treereduce-rust
```

`reduce.root` is required for `minimize`.

`reduce.contract` is required for `minimize`.

`reduce.protected` prevents known-critical files from being deleted or structurally edited.

`reduce.generated_dirs` defaults to the list shown above.

## Contract Model

The oracle checks behavior after every candidate edit.

V1 contract fields:

- `exit_code`
- `require`
- `forbid`

V1 matching:

- run the suite command
- compare actual exit code to `contract.exit_code`
- join stdout and stderr as oracle text
- require every `require` string to appear
- require every `forbid` string to be absent

Later contract fields:

- required JSON rows
- forbidden JSON rows
- exact count ranges
- normalizer-aware output matching
- rule IDs if the project output has row identifiers

## Reducer Architecture

Add a reducer module with explicit submodules:

```text
crates/fixture3/src/reducer.rs
crates/fixture3/src/reducer/config.rs
crates/fixture3/src/reducer/oracle.rs
crates/fixture3/src/reducer/filetree.rs
crates/fixture3/src/reducer/toml.rs
crates/fixture3/src/reducer/source.rs
crates/fixture3/src/reducer/proof.rs
```

Public flow:

1. Parse manifest.
2. Resolve one suite.
3. Resolve `reduce.root`.
4. Run baseline oracle.
5. Fail if baseline does not satisfy contract.
6. Reject generated folders.
7. Run filetree pass.
8. Run TOML pass.
9. Run Rust source pass through `treereduce`.
10. Run final oracle.
11. Write proof metadata.
12. Print summary.

Do not put reducer logic in `app.rs`. `app.rs` should only route CLI commands to reducer entry points.

## Filetree Pass

Purpose:

- remove whole files and empty directories before spending time on syntax reduction

Dependency:

- use `walkdir` for physical traversal
- use `std::fs` for individual delete, restore, and rename operations

Do not use Guardrail3 `g3-workspace-crawl` here.

Reason:

- Guardrail3 crawl is an ingestion-oriented snapshot, not a reducer walker.
- It uses `ignore` for gitignore-aware phase 1.
- It adds a second recovery walk for guardrail-relevant config files.
- It excludes banned trees such as `target`, `node_modules`, `dist`, `.git`, `.claude/worktrees`, and `behavior/fixtures`.
- For fixture minimization, skipped content is still fixture content.
- Generated directories must be detected and rejected, not silently hidden by traversal.
- Ignored files must be visible to the reducer because they may be accidental bloat or intentionally required by the fixture contract.

Algorithm:

1. Build a sorted candidate list under `reduce.root`.
2. Exclude protected paths.
3. Exclude proof file.
4. Exclude approved, received, and diff storage paths.
5. Reject generated directories before mutation.
6. For each file:
   - move file to a temp backup path
   - run oracle
   - keep removal if oracle passes
   - restore file if oracle fails
7. Repeat until one full pass removes no files.
8. Delete empty directories.
9. Record tried, removed, and kept files.

The pass is intentionally simple. Whole-file deletion removes the largest accidental bloat first and makes later source reduction cheaper.

## Generated Directory Gate

Generated directories are not reduced. They are rejected.

Reason:

- keeping generated folders in fixtures is a hygiene failure
- a reducer should not waste time proving that `target` or `node_modules` is unnecessary

Default forbidden directory names:

- `target`
- `.git`
- `.cargo-target`
- `node_modules`
- `dist`
- `.fixture3`
- `.goldencheck`

If any exists under `reduce.root`, `fixture3 minimize` exits `2` and reports the exact path.

## TOML Pass

Purpose:

- remove unused manifest entries while preserving valid TOML

Dependency:

- use `toml_edit`

Initial candidates:

- `[dependencies]` entries
- `[dev-dependencies]` entries
- `[build-dependencies]` entries
- `[features]` entries
- `[workspace.members]` values
- package metadata keys that do not affect the oracle

Algorithm:

1. Parse TOML with `toml_edit`.
2. Generate one semantic removal candidate at a time.
3. Write candidate TOML to the fixture.
4. Run oracle.
5. Keep removal if oracle passes.
6. Restore original TOML if oracle fails.
7. Repeat until one full pass removes nothing.

Do not use `treereduce` as the first TOML reducer. TOML reduction needs semantic candidates, not arbitrary syntax-node deletion.

## Source Pass

Purpose:

- shrink supported source files after filetree and TOML passes stop making coarse progress

Dependencies:

- use `treereduce`
- use `tree-sitter-rust`

Initial language support:

- Rust files matching `*.rs`

Algorithm:

1. Discover Rust files under `reduce.root`.
2. Skip protected paths.
3. For each Rust file:
   - invoke `treereduce` API with a fixture3 oracle adapter
   - the adapter receives candidate source bytes
   - write candidate bytes into the file location in a temp workspace
   - run the suite oracle against that workspace
   - return interesting only when the contract passes
4. If `treereduce` returns smaller source and final oracle passes, replace the original file.
5. Record changed and unchanged files.

The source pass must never call an external `treereduce-rust` binary in core logic. Use the Rust API so installs remain self-contained.

## Temporary Workspace Model

Each candidate edit should run in an isolated temp workspace when the candidate cannot be tested safely in place.

Use `tempfile` for temp directories.

Preferred model:

- filetree pass can mutate in place with backup and restore because the operation is simple
- source and TOML passes should use temp workspaces when the candidate generator can emit many variants
- final accepted edits are copied back only after the oracle passes

Directory copy policy:

- do not add `fs_extra` because it fails the activity requirement
- implement a small internal copy function only if needed
- keep it narrow: regular files, directories, symlinks as symlinks
- reject unsupported file types with an explicit error

## Proof Metadata

Write JSON proof metadata to `reduce.proof`.

Shape:

```json
{
  "schema_version": 1,
  "suite": "copied-rust-project",
  "root": "behavior/fixtures/copied-rust-project/project",
  "started_at": "2026-05-14T20:24:59Z",
  "finished_at": "2026-05-14T20:25:40Z",
  "baseline_hash": "sha256:...",
  "final_hash": "sha256:...",
  "contract": {
    "exit_code": 0,
    "require": ["\"rule\": \"workspace_root\""],
    "forbid": ["panicked at"]
  },
  "passes": [
    {
      "name": "generated-dirs",
      "status": "passed",
      "rejected": []
    },
    {
      "name": "filetree",
      "tried": ["src/unused.rs"],
      "removed": ["src/unused.rs"],
      "kept": ["src/main.rs"]
    },
    {
      "name": "toml",
      "tried": ["dependencies.regex"],
      "removed": ["dependencies.regex"],
      "kept": ["dependencies.serde"]
    },
    {
      "name": "treereduce-rust",
      "tried": ["src/main.rs"],
      "changed": ["src/main.rs"],
      "unchanged": []
    }
  ]
}
```

The proof is not hand-authored. It is generated by `fixture3 minimize`.

## Exit Codes

- `0`: reduction completed and final contract passed
- `1`: reduction completed, but at least one candidate was rejected as unnecessary to change; no error
- `2`: setup error, generated directory found, baseline contract failed, command failed unexpectedly, or final contract failed

Open decision:

- Existing `fixture3` uses `1` for behavior differences and `2` for errors. `minimize` may only need `0` and `2` because rejected candidates are normal reducer behavior.

## Verification Fixture

Add a fake copied Rust project under `examples/fake-project` or `behavior/fixtures/self/cases`.

The fixture must include:

- one required Rust file
- one removable Rust file
- one removable function inside the required Rust file
- one removable dependency in `Cargo.toml`
- one required dependency in `Cargo.toml`
- one forbidden generated folder case
- one proof metadata expectation

Expected behavior:

- generated folder fixture fails with exit code `2`
- clean copied-project fixture reduces successfully
- filetree pass removes the unused file
- TOML pass removes the unused dependency
- source pass shrinks at least one Rust file
- final `fixture3 check --suite <suite>` passes
- second `fixture3 minimize --suite <suite>` finds no more filetree removals
